# DRAG-P6 — Schedule Model Classification Gate

## Principle

DRAG is evaluated with one counterfactual definition:

\[
DRAG_i = PF_{baseline} - PF_{counterfactual,i}
\]

What changes is the scheduling model used to generate `PF_counterfactual`.

## Modes

### 1. Logic DRAG

Use when dates are governed by:

\[
Duration + Logic + Calendars + Constraints
\]

The P6 engine perturbs Remaining Duration and reschedules the calibrated temporal network.

### 2. Resource-Constrained DRAG

Required when resources actually govern scheduled dates:

\[
Duration + Logic + Calendars + Resources
\]

A valid counterfactual must re-evaluate resource availability/order after the duration perturbation. The Spider R2 laboratory currently supports a **frozen resource-order** reconstruction for the positive benchmark cases. Dynamic re-levelling remains a later layer.

### 3. Productivity-aware context

When duration is physically generated by quantity, productivity, and crew capacity:

\[
Quantity + Productivity + Resources \rightarrow Duration
\]

The current P6 engine still perturbs Remaining Duration, but labels the result so that RD is not mistaken for the physical decision variable.

## P6 decision rule

Resource assignments in `TASKRSRC` do **not** prove that resource leveling governed the schedule. P6 resources can be used only for cost, workload, or reporting. Therefore:

1. Detect what is present in the XER.
2. Ask whether resources actually drive scheduled dates when this cannot be proven.
3. Label the result by the model actually solved.
4. Never present a Logic DRAG result as Resource-Constrained DRAG.

## Current engine boundary

If the user confirms that a P6 schedule is resource-levelled, v1.1.0.0 R3 labels the current result:

**LOGIC DRAG — DIAGNOSTIC ONLY**

until dynamic P6 resource re-levelling is implemented.
